# Writing Harness · 门禁体系

> 由 derekwritting-framework 注入，写作门禁与评测循环已就位。
> 设计原则：门禁是护栏，不是路障——兜住已知的坑，不拦诚实的表达。

---

## 七道门禁（G0-G6）

每篇文章从立项到发布，经过七道门禁。越往前的门禁，成本越低；越往后的门禁，兜住的问题越严重。

```
G0 立项门禁 ── 这篇文章值得写吗？（动笔前）
   ↓
G1 风格门禁 ── 有没有 AI 味？（完稿初筛）
   ↓
G2 结构门禁 ── 读者能不能跟上思路？（段落级检查）
   ↓
G3 事实门禁 ── 论断有没有依据？（事实核查）
   ↓
G4 链接门禁 ── 引用能不能对得上？（交叉验证）
   ↓
G5 评审门禁 ── 整体质量过不过线？（rubric 评测）
   ↓
G6 发布门禁 ── 涟漪 + 上线检查（发布前最后一道）
```

---

## G0 · 立项门禁（动笔前）

> 对应 derekcoding-framework Bad90 Q2：这件事真的有价值吗？

在写任何一篇文章之前，先过 G0——用五个问题判断"这篇值不值得写"。

| 问题 | 检查点 |
|------|--------|
| 这篇的核心主张是什么？ | 能用一句话说清楚吗？说不清楚 = 没想好，别写 |
| 读者看完能带走什么？ | 一个新认知？一个可复用的方法？还是只觉得"写得不错"？ |
| 社区里有没有人讲过？ | 如果讲过，我们的增量是什么？——新项目实证？更系统的框架？反常识的观点？ |
| 有没有真实项目实证？ | 四个项目里能不能找到对应的文件 / 数字 / 经验？没有实证的观点，不单独成篇 |
| 系列定位匹配吗？ | 这篇是在"治理 AI 生成物"的主线上，还是跑题了？ |

**G0 不过 = 不写**。宁可少一篇，不写注水篇。

## G0a · 量纲门禁（公开发表字数）

> 2026-09-24 新增。硬性：**公开发表时会去掉的两 part 不计入正文量纲**，正文必须自己撑到目标字数。

序列每篇正文末尾附两 part——「第一天就能用的清单」（中文）/「Takeaway」（英文），以及「附：门禁评审记录」/「Appendix: Gate Review Record」。这两 part 是工程留痕，公开发表时会剥离，因此**不计入字数**。

正文量纲以去掉这两 part 后的"已发布正文"为准：

| 语种 | 指标 | 硬阈值 | 目标 |
|------|------|:---:|:---:|
| 中文 | 已发布正文汉字数（不含清单 + 门禁评审两 part） | ≥ 2800 | ~3000 |
| 英文 | 已发布正文单词数（不含 Takeaway + Appendix 两 part） | ≥ 1900 | ~2000 |

剥离规则以正文中第一个 strip 标记为界截断计数。计数工具与硬门禁：

```bash
# 全量复核（根目录）
python scripts/body_wordcount.py --all
# 单篇
python scripts/body_wordcount.py articles/01-trust-crisis.zh.md
python scripts/body_wordcount.py articles/en/01-trust-crisis.en.md
```

**反注水纪律**：扩正文不是堆字数。每个新增模块必须满足"删掉它 → 主线论证就少一环"；新增数字必须带来源标记（中文 `[内部项目实测]` / `[实测]`，英文 `[ORIGINAL DATA]`）并通过 G3/G4 事实与链接门禁。

## G1 · 风格门禁（完稿初筛）

检查 AI 味 / 信号词密度。

| 项 | 阈值 |
|----|------|
| 信号词密度 | < 6 / 千字 |
| 五维自评（直接/节奏/可信/真诚/密度） | < 35 / 50 必须重写 |

```bash
python3 writing-harness/writing-gates.py <file.md> --gate g1
```

---

## G2 · 结构门禁（段落级检查）

检查读者能不能跟上思路。对应 derekcoding-framework 的 Purpose-First 原则。

| 检查项 | 标准 |
|--------|------|
| 段首给答案 | 每段第一句就是这段的核心观点 |
| 每段一个职责 | 一段只讲一件事，不混用 |
| 过渡自然 | 段与段之间有逻辑衔接，不跳 |
| 清单是清单，段落是段落 | 不用列表替代论证，不用段落堆清单 |
| 结尾收得住 | 每节有小结 / 过渡句，不戛然而止 |

```bash
python3 writing-harness/writing-gates.py <file.md> --gate g2
```

---

## G3 · 事实门禁（事实核查）

检查论断有没有依据。对应 derekcoding-framework 的"验证优先"原则。

| 检查项 | 标准 |
|--------|------|
| 统计主张有来源 | 百分比 / 倍数 / 排名，必须有可追溯的来源链接 |
| 项目数字可指认 | 来自四个项目的数字，能指认到具体文件 / 目录 |
| 不引用精确 star 数 | GitHub 项目只用相对定位（头部 / 中腰部） |
| 一手经验标清楚 | "我在 aITMS 上的经验" vs "行业普遍情况"，不混淆 |
| 没有未溯源的断言 | "研究表明""数据显示"类表述，必须有出处 |

```bash
python3 writing-harness/writing-gates.py <file.md> --gate g3
```

---

## G4 · 链接门禁（交叉验证）

检查引用 / 链接 / 内部一致性。

| 检查项 | 标准 |
|--------|------|
| 外链有效 | 外部链接不 404 |
| 内链对得上 | 引用本系列的篇号、标题，与最新目录一致 |
| 术语统一 | 全文术语一致——不出现同一概念两种叫法 |
| 数字不打架 | 同一项目的同一个数字，前后一致 |
| derekinside 暗线对齐 | 每篇的 derekinside 注脚位置 / 浓度，符合宪法第五章 |

```bash
python3 writing-harness/writing-gates.py <file.md> --gate g4
```

## G5 · 评审门禁（rubric 评测）

整体质量过不过线。10 维 rubric，LLM as Judge。

| 维度 | 说明 |
|------|------|
| Clarity | 读起来清不清楚 |
| Audience | 目标读者会不会觉得有用 |
| POV | 有没有鲜明的观点 |
| Specificity | 够不够具体，不是空泛的 |
| Insight | 有没有新认知 |
| Structure | 结构合不合理 |
| Voice | 声音一致、真诚 |
| Usefulness | 读者能不能直接用 |
| Trustworthiness | 可信不可信 |
| Memorability | 记不记得住 |

**阈值**：均值 ≥ 3.5 / 5

```bash
python3 writing-harness/judge.py <file.md>
```

## G6 · 发布门禁（上线前最后一道）

对应 derekcoding-framework 的 Pre-Deploy Gate + Ripple Analysis。发布前做最后一遍检查。

| 检查项 | 说明 |
|--------|------|
| 涟漪检查 | 这篇的观点 / 术语 / 篇号，会不会影响系列其他篇？ |
| 宪法合规 | 有没有违反宪法第二章的写作铁律？ |
| 暗线合规 | derekinside 出场方式符合宪法第五章吗？ |
| 清单可操作 | 结尾的"第一天就能用"清单，真的第一天就能用吗？ |
| 标题与摘要 | 标题不标题党，摘要准确概括内容 |
| 平台适配 | 首发平台的格式 / 字数 / 图片要求，都满足吗？ |
| 剩留问题 | 已记录在门禁评审记录里，不带病隐瞒 |

G6 是人工门禁——由非写作者执行，评审与写作分离。

---

## 门禁纪律

1. **顺序不可逆** — G0 不过不动笔，G1 不过不进 G2，以此类推
2. **门禁是发布前，不是写作中** — 写作时套门禁会扼杀表达；完稿再跑
3. **门禁失败 → 回对应阶段修** — 不是在门禁上打补丁，是回文章里改
4. **门禁通过 ≠ 完美** — 记录剩留问题清单，诚实标注
5. **评审与写作分离** — G5 / G6 不由写作者自己执行
6. **反馈回写（2026-08-28 新增，对齐 ADR-0003 双向反馈）** — 门禁不是单向流水线的终点。门禁反复拦下的同类问题，要能流回规约层：是检查项不够、是 spec 模板缺位、还是宪法原则有误？能指认具体层就升级那一层，让下一篇不再踩同一道坑

---

## 反馈回写通道（上行矫正示例）

| 反复出现的问题 | 回写动作 | 目标层 |
|--------------|---------|--------|
| 同一概念两种叫法 | 术语表补一条，全系列替换 | 契约层（spec 模板） |
| 某类实证总被质疑 | 补进"实证边界"检查项 | 门禁层（G3 事实门禁） |
| 读者总误解某个比喻 | 宪法补一条"类比要标注" | 战略层（宪法） |
| 用户改稿反复指向同一处 | 提炼成写作原则，回写宪法 | 战略层（宪法） |

## 用法

```bash
# 跑全套门禁（G1-G4 自动 + G5 评测 + G6 人工检查清单输出）
python3 writing-harness/writing-gates.py <file.md>

# 只跑某一道
python3 writing-harness/writing-gates.py <file.md> --gate g1
python3 writing-harness/writing-gates.py <file.md> --gate g3

# 查看信号词表
python3 writing-harness/writing-gates.py --list

# rubric 评测（需配置 LLM API）
python3 writing-harness/judge.py <file.md>
python3 writing-harness/judge.py --list    # 查看 10 维 rubric
```

## 设计依据

- **derekcoding-framework Gate Design**：G0-G6 阶段框架、三道门禁问题（防什么 / 在哪拦 / 自动还是手动）
- **derekcoding-framework Bad90 Self-Check**：G0 立项门禁的五问法，源自 Q1 阶段 + Q2 价值
- **derekcoding-framework Ripple Analysis**：G6 发布门禁的涟漪检查
- **顶级开源项目 CI/CD 实践**：门禁分层、失败回退、自动化优先
