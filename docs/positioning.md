# MultiAgent Fabrication · 特色主张与差异化

> 版本：v1.0 ｜ 2026-09-05
> 回答一个问题：与 GitHub 高分多 Agent 体系相比，本系列凭什么有自己的特色？

---

## 一、一句话特色

**多 Agent 的生产力不在"编排得漂亮"，而在四链路闭环可自证——选型、调用、校验、自愈全部声明式 + 可复现，外加一条别家没有的纪律：宣称对齐。**

---

## 二、别人没回答的命题

制表三问（社区几乎无人系统回答）：

| 问 | 我们的答案 |
|:--|:----------|
| 怎么选模型（而不是"用一个框架"）？ | 多维约束求解，声明式 + 渐进松弛 + 显式失败（method 19 Resolver） |
| 怎么让多 Agent 出结果**可信**（而不是"能出结果"）？ | golden data 本地自评 + 精度加权共识 + 防分母错觉 |
| 怎么证明它**真的更高效**（而不是"看起来很厉害"）？ | 基准对照 + 参数版本快照 + decision.db 全链路审计 |

这三个问题，主流框架一个都没正面回答。它们教你编舞，不教你证明舞跳得多好、为什么值得跳。

## 三、四大差异支柱（每篇正文必须能指认到其中至少一个）

### 支柱 A：约束求解式选型（不是 fallback）
- 别家：线性 fallback / 条件路由。
- 我们：`_filter → _relax → _rank` 多维约束求解，健康优先，显式失败，绝不同声部静默落未知。

### 支柱 B：可自证的校验（不是"看起来对"）
- 别家：外部 LLM 打分 / 多数投票。
- 我们：golden data 本地离线评测 + 精度加权 + 防分母错觉（单高精度命中不被缺席者稀释）。

### 支柱 C：宣称对齐的诚信底线（信誉即生产力）
- 别家：README 写"能做到"。
- 我们：宣称要么接 CI 可跑验证，要么标注"目标值/规划"。审查报告最爱点这条。

### 支柱 D：全链路审计归因（生产力可复盘）
- 别家：结果到 Agent。
- 我们：结果到参数版本快照，decision.db 记录每次决策，可归因、可复盘、可回流为下轮输入。

## 四、与姊妹系列的分工

- 《RefactoringSoftwareEngineering》回答"把管理方法本身也管起来 / 把软件工程工序重做一遍"。
- 《MultiAgent Fabrication》回答"用一群 Agent / 多个模型，怎么真的形成生产力"。
- 关系：Multi-Agent 是 RefactoringSoftwareEngineering 的**核心延伸**——前者提供"多 Agent 造东西"的引擎，后者把造出来的东西与治理管成体系。
