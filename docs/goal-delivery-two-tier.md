## 一、这一套的核心理解（吃透的结论）

SmartQuant 里的多 Agent 不是一层，而是嵌套的两层，二者有**先于时间的不对称**：

| | 元 Agent（m层 / 开发态） | 产品 Agent（p层 / 运行态） |
|---|---|---|
| 性质 | 建筑工人 + 工厂，组件软件 | 被制作出来的专家角色，在目标产品里当班 |
| 出场时序 | 先于产品 Agent 存在 | 由元 Agent 造出 |
| 负责对象 | 「这个东西凭什么能信、坏了怎么修、规则怎么改」这一整本账 | 「现在这份输入该怎么处理」 |
| 知识总线 | 只读 k1（规则）+ k2（会话） | 读 k1 + k2 + k3（长期记忆） |
| 对长期记忆 | 不信 k3（不背运行期旧案） | 才有资格读 k3 |

一句话：**元层是工厂，产品层是车间；两层的记忆各自记账，经验只沿 k4 那条带审计的单向管道回流。**

### 记忆体系：k1-k4 四层知识总线

- **k1 规则层**：宪章 / 编码十诫 / 方法论 / 红线。静态、文本可审，进场必带。
- **k2 会话工作记忆**：本轮滚动上下文，滑动窗口摘要，超限压缩、扛不住安全丢弃。
- **k3 长期情节记忆**：偏好 / 策略上下文 / 标的 / 裁决 四类；带 source_run_id 溯源、confidence 置信度、content_hash 去重。
- **k4 跨层记忆回流**：不存记忆、运记忆；单向 + ADR 审计 + 人终裁，产品层经验升格为元层规则。

**关键设计**：这两层的价值不在字段细节，而在它把"谁的记忆算谁的"变成可审计问题。一旦产品层能直接写元层规则，两层就糊成一层，分层前功尽弃。
