> 调研结论先说：没有任何一个框架把「多 Agent 形成的生产力」本身作为一个**可度量、可自证、可回馈生产流程**的命题来回答。它们教你"组织长什么样"，没有人回答"怎么证明组织真的更高效"，且不处理"生产成本与治理"。

## 二、逐谱系方法论提炼

### 2.1 MetaGPT：流水线 SOP 心智

- **组织心智**：把软件公司分工（产品经理 / 架构师 / 工程师 / QA）编码成一条**标准化生产流水线**，Agent 之间靠**结构化报文（文档 / 代码 / 数据）**传递，形成标准件。
- **可借鉴**：结构化产物契约（类 ADR / 契约层的工程实体）——Agent 间不靠自然语言闲聊，靠可被下游当作输入的规范件。
- **局限（与我们的差异）**：依靠单一路径回到上游失败时整条线重跑，缺少方法 19 的**多维约束求解选型**与**多模并行加权共识**。流水线擅长度流程，不擅长处理"选哪个模型 / 哪个 Agent"的异构资源。

### 2.2 AutoGen：对话网格 / Actor 心智

- **组织心智**：多智能体自由会话，节点即 Actor，可嵌套、可替换，支持人机混合协作。强调"让 Agent 自己谈出结果"。
- **可借鉴**：Actor 可插拔 + 人工可介入（HITL 的雏形）。
- **局限**：自由会话缺乏**显式约束与门禁**，容易出现"多数弱智共识 / 跑题循环 / 责任不明确"。其多数非确定性来自对话，而我们强调**精度加权 + 防分母错觉**，防止对话式投票被平庸多数主导。

### 2.3 LangGraph：状态图状态机心智

- **组织心智**：把多 Agent 系统的执行流建模为**图**，节点是状态 / 心智，边是条件迁移，支持持久化与循环。天然能表达"回退 / 重试 / 条件分支"。
- **可借鉴**：显式状态迁移 + 执行可回放（审计友好）。
- **局限**：图本身不承载"选模型"的约束；路由常是**条件跳转（近似线性 fallback）**，而不是方法 19 的多维约束求解 + 渐进松弛。

### 2.4 CrewAI：层级委派心智

- **组织心智**：Role / Task / Process 三层结构，leader-worker 委派，强调"团队"而非"市场"。
- **可借鉴**：责任切分（Role）与任务分解（Task）对 SmartQuant 9 角色 registry 有参照。
- **局限**：对"角色如何被路由、如何被门禁、其结果如何被审计归因"覆盖弱——这些正是 SmartQuant 用三层路由 + decision.db 补齐的部分。

### 2.5 OpenAI Swarm：无状态轻量心智

- **组织心智**：官方定位是**实验性 / 教学性质**的无状态轻量编排，靠 Handoff 在 Agent 间移交对话控制权。
- **可借鉴**：轻量起步——验证"多 Agent 是否真的值得"的探针。
- **局限**：无状态意味着不持久、不审计、不可归因，天然不适合需要决策留痕的生产系统。其存在本身就是"编排 ≠ 生产力"的脚注。

### 2.6 TradingAgents：辩论 + 审批心智

- **组织心智**：金融投研场景，分析师 Agent 多头辩论（看多 vs 看空 vs 中立），风控 Agent 审批撮合，产出带风险标注的投资建议。
- **可借鉴**：**对抗性多视角 + 明确审批闸门**——辩论不是为了制造多数，是为了挖掘盲点；审批是生产力放行的最终约束。
- **局限**：靠外部模型产出的质量难以自证；缺方法与 golden data 基准对照，也缺"宣称对齐"的自检。它红了，但仍属于"Demo 级生产力"，离工程闭环差审计与退化。

### 2.7 RD-Agent：量化硬门禁心智

- **组织心智**：数据驱动的研究自动化，生成-评测-迭代闭环，**回测不过不放行**——硬门禁是生产力可信的最后防线。
- **可借鉴**：**证据追溯 + 硬门禁**（与 SmartQuant G1-G7 + 证据归档是同一信念，也和 TradingAgents 的审批一脉相承）。
- **局限**：门禁对象是量化指标；对"多模型选型 / 观测 / 共识"这类多 Agent 通用件覆盖不足。

### 2.8 STORM：多视角成文心智

- **组织心智**：多专家轮询提问 → 搜索佐证 → 大纲聚合 → 成文。多视角用于**信息完备度**而非"决策正确性"。
- **可借鉴**：多视角能提升覆盖（recall），而非精度。这启发我们区分"多 Agent 用于覆盖" vs "多 Agent 用于校验"。
- **局限**：成文质量依赖外部素材可信度，缺 golden data 自评估；只在检索域有意义。

## 三、横向共识与分歧

### 3.1 七条共识（高分项目几乎都体现）

1. **结构化产物优于自由闲聊**：MetaGPT 报文 / LangGraph 状态 / STORM 大纲——Agent 间传递规范件。
2. **人工必须可介入**：AutoGen HITL / TradingAgents 审批——人是循环的一环。
3. **要让多 Agent 出结果需某种门禁或评审**：RD-Agent 回测 / TradingAgents 风控。
4. **工具调用需受控**：各家都收敛到受约束的工具 / 函数调用。
5. **状态与过程最好可回放**：LangGraph 持久化 / 审计偏好。
6. **多 Agent 是有成本的，要有取舍理由**：Swarm 轻量 / 各家都强调"单 Agent 够用就别多上"。
7. **角色 / 责任要先切清楚**：CrewAI Role / SmartQuant 9 角色 / MetaGPT 分工。

### 3.2 五大分歧（本系列的差异化机会）

| 分歧 | 主流做法 | 我们的主张 |
|:----|:---------|:----------|
| 选型 | 线性 fallback / 条件路由 | **多维约束求解 + 渐进松弛 + 显式失败** |
| 校验 | 外部 LLM 打分 / 多数投票 | **golden data 本地自评 + 精度加权 + 防分母错觉** |
| 观测 | 主动轮询健康 | **搭便车被动观测 + 指数退避深探** |
| 宣称 | 文档写"能做到" | **宣称必须对齐（可 CI 跑或标目标值）** |
| 归因 | 结果到 Agent | **结果到参数版本快照 + decision.db 全链路** |
