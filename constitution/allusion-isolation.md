# 宪法 · 中英典故隔离表（Allusion Isolation）

> 分级：软约束（靠评审人工核查，不进入脚本硬门禁）。
> 来源：适配自 derekwritting-framework `constitution/allusion-isolation.md`（Apache 2.0）；本文档是本系列《MultiAgent Fabrication》的可复副本。
> 用途：解决"引经据典依赖作者文化积累，尚无自动检查手段"的剩留问题，供中文主场与英文 essay 双语写作共用一套判定。

## 零、与本系列关系

- 本表是 `docs/WRITING-FRAMEWORK.md` 第四节"引用纪律"的落地执行件；任何 2-3 处引用在落稿前先过本表 R1-R4 判定。
- 与 `docs/WRITING-FRAMEWORK.md` 第六节"矿源占用现状"联动：占用表列出本系列**不可复用**的引用，本表给出**可用性判定规则**，二者一文管口径、一表管判定。

## 一、判定规则

一篇稿子从"引经据典"滑向"掉书袋"或"文化出戏"，通常违反下面四条之一：

| 规则编号 | 规则 | 触碰后果 |
|----------|------|----------|
| R1 | 典故必须直接支撑论证，删掉后论证要明显变弱 | 硬删 |
| R2 | 中文稿不得使用"唯有英文读者才懂"的西方冷门典故 | 硬删或加一句解释 |
| R3 | 英文稿不得直接套用需要中文文化背景才能 get 的名句/成语 | 硬删或改写为英语母语者熟悉的等价表达 |
| R4 | 一篇稿典故总量控制在 2-3 个，最多 4 个 | 超标则删最弱 |

判定顺序：先查 R2/R3 隔离，再查 R1 相关性，最后查 R4 数量。

## 二、面向的读者对象（决定隔离方向）

- **中文主场**（腾讯云开发者社区，读者为中文技术负责人 / 架构师）：可引用中文传统典故、科技史、通用管理思想；西方冷门作家名言需给一句背景。
- **英文 essay**（海外工程师 / native 读者）：可引用英语世界通行典故、开源史 / 硅谷史、通用管理思想；中文成语、古典名句、西化生造的典故一律禁用。
- **本系列特有**：引用宁可少而硬，优先选前序未用矿源（系统论 / 组织管理 / 开源历史 / 哲人名言），删掉后论证变弱才有效。

## 三、中英隔离清单

标注：🟢 双语境通用（两边都能用）｜🟡 限一侧（另一侧需改写）｜🔴 禁止跨语境直用

| 典故/引用 | 分类 | 中文稿 | 英文稿 | 说明或改写建议 |
|-----------|------|--------|--------|----------------|
| 庖丁解牛 | 中文典故 | 🟢 | 🔴 | 英文读者无感；如需可改写为 "understanding the system down to working parts" |
| 坐井观天 | 中文成语 | 🟢 | 🔴 | 英文直译生硬；改 "a narrow mental model" |
| 拔苗助长 | 中文成语 | 🟢 | 🔴 | 等价 "overengineering too early / premature optimization"，建议直接讲工程后果 |
| 蝴蝶效应 | 通用隐喻 | 🟢 | 🟢 | 双语境都懂 |
| 墨菲定律 | 通用谚语 | 🟢 | 🟢 | 双语境都懂 |
| 爱迪生"1%灵感" | 英文名人名言 | 🟢(给背景) | 🟢 | 英文稿可直接用；中文稿可带一句出处背景 |
| "move fast and break things" | 硅谷典故 | 🟢(给背景) | 🟢 | 英文稿可作共享暗号 |
| "don't repeat yourself" (DRY) | 软件谚语 | 🟢 | 🟢 | 工程语境通用 |
| "first principles" | 通用管理/物理思想 | 🟢 | 🟢 | 双语境通用 |
| "Chesterton's Fence" | 西方冷门典故 | 🟡(需解释) | 🟢 | 中文稿需一句话解释其含义，否则读者掉队 |
| 守株待兔 | 中文典故 | 🟢 | 🔴 | 英文读者不知出处；改 "expecting a great outcome to fall into your lap" |
| 网开一面 / 留一分余地 | 中文成语 | 🟢 | 🔴 | 英文稿直接说 "leaving a release valve / a fallback path" |

> 清单是起点不是终点。新增典故请按 R1-R4 规则评定后补表，并在对应语言一侧标注可用性，防止后续稿件误用。

## 四、违规示例与改写

**例 1（英文稿误用中文典故）**

- 违规："Tuning this config is like 庖丁解牛 — you must move fluidly through the cuts."
- 问题：English-native 读者无感，且不会 pause 去想一个中文典故。
- 改写："Tuning this config is about reading the system's grain — once you see how each knob relates to the next, the changes stop fighting each other."

**例 2（中文稿误用西方冷门典故）**

- 违规："这套设计遵循 Chesterton's Fence 原则，先搞懂再拆。"
- 问题：多数中文读者不知出处。
- 改写（补背景）："这就像 Chesterton 的栅栏原则——先搞清这道栅栏为什么立在这，再决定拆不拆。"

**例 3（引用与论据脱节 / 掉书袋）**

- 违规："运用之妙，存乎一心。优化就该像这样。"（删掉后论证毫无变化）
- 问题：R1 违规，纯装饰。
- 修订：删掉，或替换为能支撑下一句的工程类比。

## 五、与门禁 / 评审的对接

- 本文档是**软约束**：不进入 `writing-harness/writing-gates.py` 的脚本硬门禁（典故依赖语境，机器误判率高）。
- 落点：评审团队的**文风审查员 + 读者代表**在 G5 前核对此表（`writing-harness/review-swarm-prompt.md` 的角色 2 与角色 5）。分离评审者与写作者，是 G5 硬性要求。
- 双语成稿：翻译稿必须重跑一次隔离表，因为"中文稿可用"的典故在英文稿多半是 🔴。
- 若后续积累足够多违规样例，可考虑给 `writing-gates.py` 增加一个可关停的 C-flag，但默认关闭。
