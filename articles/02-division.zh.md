# 分工是判断的可重构

> 不是人多，是责任可切——把一次前向推理，切成一条能彼此指认责任的流水线。

## 一、一个被"分工"救回来的乱摊子

续上一篇的教训。我们在链路上吃过单点判断器的亏之后，第一反应通常都是一样的：加模型、加轮数、换更强的底座。结果呢？更贵、更慢，错还是错——只是错得更体面。后来我们发现，真正把局面掰回来的，不是任何一次"换更强的模型"，而是一次彻底的**重构：把一个人能拍板的事，拆成一组彼此能负责的人。**

我说一个具体的转身。早期一个链路里，判断一个方案到底该不该上线，依赖的是"一个 Agent 看完所有材料拍板"。它大部分时候对，但这个"大部分时候"掩盖了一件致命的事——没人知道它哪一环会出错。于是我们把它拆成了三层：第一层负责"这个需求该怎么拆、该找谁论证"（调度），第二层负责"给出论证、给出可测的约束、接受对抗审查"（执行），第三层负责"把这次结论、它的依据、它被证伪还是被采纳，全部留痕归档"（知识）。

结果出乎意料：每一次出错，我们都能在十分钟内说出"这轮是拆错需求了，还是论证有漏洞，还是留痕漏了一条"。判断没有变聪明，但**它第一次变得可以被管理了。** 这就是分工的真相——它不是靠堆人头换质量，而是用切分换可问责，用可问责换可管理。

## 二、为什么黑盒能被切开，以及切成几层才够

很多人以为多 Agent 的"多"就是数量问题。这是本系列要反复纠正的幻觉。**单点判断器能被切开，不是因为模型多，而是因为它里面的四个环节——理解、拆解、执行、自检——本来就是四种不同的动作，只是被熔在了一次前向推理里。** 逐层问每一个模型，谁都不能向你交代；但把这四个动作分给四类明确的职责，每一类就能单独被检验。图 1 把这条链画出来了：从"一次前向推理"的黑盒，到调度 / 执行 / 知识三层。

那么切成几层才够？答案不是"越多越好"，而是**切到每一份责任的边界能被人指认为止。** 我只用三层，不是三层最优雅，而是三层恰好把三种不同的"可"分开了：调度层可指认（这次活儿是谁派错的）、执行层可证伪（这个方案能不能被反驳）、知识层可复核（这个结论的依据全不全）。再多切，边界就开始模糊，反而退回黑盒。

这里要特别说破一层伪装：**"多轮追问同一个 Agent"绝不是分工。** 你说"再想想",它"再想想"，本质上还在同一个黑盒里打转，只是把熔在一起的环节重复烧了一次。分工的定义边界是：**不同环节由不同的、可被分别指认的对象执行，且环节之间有明确的交接与问责缝。** 追问不制造问责缝，只会制造更厚的黑盒。

## 三、不是人多，是责任可切：和 CrewAI 的一对比

这一篇最重要的对照，是和主流框架的一次坦诚对话。CrewAI 教给我们一件好东西——**角色（role）**：把一个 Agent 定义成"研究专员""审查员""决策者"，让不同的 prompt 和工具去承担不同的活。这已经是在切分工了，而且方向完全正确。

但我们的经验里，角色只解决了"分工的一半"。**角色定义了"该叫什么名字"，却没定义"出错了怎么算账"。** CrewAI 的组合通常解决"谁做什么"，很少解决"谁对它做的负责、用什么证据负责、出了岔子在哪个环节被抓住"。于是很多用 CrewAI 搭出来的多 Agent，看起来角色分明，实际上还是一个"各司其职、无人问责"的松散外包——出错时依旧是"整体不对"，依旧无从定位。

Multi-Agent 和它们的区别，正在于此：**我们把责任的可切性当作第一性约束来设计，角色只是可切性落地后的副产品。** 三层不是三种 prompt 的堆叠，而是三条问责缝——调度对"派对活"负责，执行对"论证可证伪"负责，知识对"留痕可复核"负责。分工首先要切开的是责任，其次才是角色。

CrewAI 的角色字段值得再拆一层看，因为缺的东西恰恰藏在字段里。一个 Agent 的定义通常包含 `role`（叫它什么）、`goal`（它想达成什么）、`backstory`（它的人设背景）三个字段，再加挂工具和一个 `llm`。这些字段把"身份"写得非常清楚，但对"交接"只字未提——两个角色之间传出去的结论，由哪个字段记录它传给了谁、原样传了没有、对方有没有照单收敛？去翻 CrewAI 的编排图，我们看到的是 `dependencies` 和 `process` 决定流程怎么走，却没有一张内置的账本去问"这一棒到底落在谁手里、掉没掉"。所以 `[内部项目实测]` 里，用 CrewAI 搭出来的角色越细分，出错时越像"拼图少了一块"，却永远说不清是哪块：身份有名字，交接没有缝。

## 四、一次"切错了层"的返工

分工不是一劳永逸的切一刀，切错了同样会翻车。我在另一个项目里就有过一次典型的返工。

早期我们照搬了"三层"的壳，但这三层的**职责边界是糊的**：调度层偶尔自己上手执行，执行层偶尔自己补留痕，知识层偶尔还想当裁判。结果是最常见的那种失败——**三个角色互相推诿，谁都不为最终结论负责，因为责任缝被糊掉了。** 出错时，调度怪执行"你没照约束做"，执行怪调度"你派的活就不对"，知识层在旁边说"我记录的都是你们喂的"。整条链退回了另一个版本的信任危机。

返工的关键，是把前面那套"三种可"重新焊死：**可指认、可证伪、可复核，三者的对象必须互斥。** 我们给每一层写死了一份契约——调度不产出方案，只产出"派给谁 + 为什么派给它"；执行不直接写进账本，只产出"可被反驳的论证 + 可复现的基准"；知识层不评判对错，只负责"事实入库、可信度校准、坑位复盘"。缝一旦清楚，分工才真正成立。

把这份契约摊开，就是三根对照柱，每一层对"交付了什么、靠什么作证、错了抓哪个缝"各说一句：

| 层 | 只交付 | 用哪份证据自证 | 错了从哪条缝抓 |
|:-:|------|------|------|
| 调度 | 派给谁 + 为什么派给它 | 派单记录（含时间戳、目标、负责 Agent） | 这一棒派错在哪 |
| 执行 | 可被反驳的论证 + 可复现的基准 | 复现脚本 / 输入输出样本 / 对抗审查记录 | 论证缺口在哪一步 |
| 知识 | 事实入库 + 可信度校准 + 坑位复盘 | 留痕行（含依据、被证伪否、回流入账时间） | 依据漏了哪一条 |

这张表的价值，是让"分工"从一句口号变成一张能对账的底单。`[内部项目实测]` 里，返工后的团队不再开会吵"谁该负责"，而是直接翻某一列：这轮留痕行少了时间戳，第一时间指向知识层，而不是整条链背锅。

反过来，"追不到人"是分工最常见的假死。团队里有过一份纸上责权表——写得很全，每种角色都有一行——可实际跑起来时，调度把活派给"执行团队"而不是一个具名的 Agent，执行把结论写进一个没人复核的便签，知识层的留痕根本没有落盘。等到出了问题，表上每个角色都占了责任行，现实里却没有一个人能站出来说"这轮是我拍错的"。**责任表是画出来的，拷问才是焊出来的：真正能指认的那只手，永远比"理论上该负责的岗位"多一截冷汗。**

## 五、分工的粒度悬崖：切到多细才不是切

前面说"切成几层够"，但那只是纵向上切多深。分工还有第二个方向——横向上每一层切多细。这个方向最容易翻车，因为它藏着一个**粒度悬崖：边界太粗，退化成黑盒；边界太细，退回另一种黑盒。** 所谓太细，不是"切得不够优雅"，而是当环节多到人无法在脑子里同时握住所有缝时，每一道缝都变成了不可指认的缝——于是再次掉回"整体不对、无人问责"。

道理很直白：**切分的目的是让"哪一环"能被指认，而不是让环节的数量变得无穷多。** 一个判据同时向上、向下划定边界：任何一次失败，如果能由**恰好一个且可被点名的人**承认"是我这一环的缝"，粒度就是对的；如果出现"好几个环节都可能、但没有一个确定"，要么是太粗（缝太宽），要么是太细（缝太多，谁也说不清）。我见过把调度又拆成"拆解岗 + 派发岗 + 复核派发岗"的项目，结果一次典型的调度错误，三个岗都能沾边，谁都不认——那已经不叫分工，叫把黑盒切碎了再各自贴一个名字。

所以分工的管理者是"人能不能指认"，不是"图好不好看"。`[内部项目实测]` 里，我们给每个新环节设的追加门槛就一句：**这个环节如果删掉，谁会对它负责的责任就立刻消失——那它该留；如果删掉后没人察觉，它从一开始就是颗粒度噪音。** 顺着这条往下，"切了之后还连得住、管得住"的下一棒，才真正交得出去。

## 六、原理飞升：判断 = Σ 可被指认的环节

再抽象一层，得到第二篇的落点：

> **一个复杂的判断，等价于一组彼此可指认、可证伪、可复核的环节之和。** 分工的价值不在"拆开了更有效率"，而在"拆开了才能被管理"——因为你终于可以对"哪一个环节"问责。

这条原理同时廓清了两件事。第一，它解释了为什么单 Agent 有天花板：**它不坏在能力，坏在不可切。** 一个不可切的整体，无论多强，出错了都没有可下手的地方。第二，它预告了多 Agent 的真正使命：**多 Agent 不是"多个判断者投票"，而是"一个判断被切成可审计的工序"。** 是切分和问责，把判断从不可管理变成了可管理。

这也给下一篇递了棒。《三条轨与三权》要回答的问题是：**分工之后，怎么保证每一环都真的负责？** 答案是三轨并行与三权分立——把"该做什么""出了什么问题""做对没有"三条线分开追，把报告、修复、验证三件事拆给三双不同的手。分工解决"可切"，三轨三权解决"切了之后还连得住、管得住"。从"切对"，到"管住"，正是多 Agent 从构图走向治理的那一步。
