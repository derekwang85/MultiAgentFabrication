# 生产力的可编程化

> 我盯着 Multi-Agent 想明白了它到底在改什么：它不是让判断做得更快，它是把判断本身变成一个可以被分工、被校验、被审计的东西——脑力劳动从个人的天赋，变成了系统的产物。这一换，比换引擎更狠，是换了生产方式。

## 一、判断是最后一种没被工业化的技艺

人类把体力劳动工厂化用了几百年：分工、标准化、流水线、可复制的图纸。可脑力劳动一直停在作坊阶段——判断长在某个人的脑子里，张三的直觉搬不到张三，专家的眼光一退休，机构就跟着瞎一截。这是生产力结构上最后一块没被工业化的地方，也是多 Agent 这套东西真正要动的那个位置。

但我要把话说得更准一点。多数人看多 Agent，以为它不过把"更快地出一个答案"这件事重复了很多遍；可 Multi-Agent 的落点在别处。它做的不是让单个判断变快，而是**让"做判断"这个动作第一次可以被分工（切给不同 Agent）、被校验（有独立一方复核）、被审计（每笔留痕）**。判断从一次性的天才表演，变成可编程、可复制的生产资源。

我给第十一篇立的靶子：**多 Agent 是一次生产力结构的迁移——判断力从个人身上，迁移到可验证的系统里。** 这不是效率的线性提升，是脑力劳动生产方式的结构性改写，像当年的蒸汽机改的不是"马多拉几车"，是"动力能不能离开畜力而存在"。

作坊阶段的判断有一个躲不开的天花板：它不可替换。一个团队里最长于某类判断的人一旦休假、离职或状态波动，那条链的能力就跟着塌一截，而旁人不是不想接，是接不住——因为判断长在他脑子里，既没被写成规则，也没被留过验证。Multi-Agent 治的正是这个天花板：把不可替换的判断，拆成可分工、可校验、可回流的几段，让"能力"第一次可以不依附于任何一个人而存在。

## 二、一般智力：思想被写进机器里的那个预言

想给"判断从天赋变成资源"找一个理论坐标，我往一个源头借。马克思在《政治经济学批判大纲》（Grundrisse）里放进一个后来叫"general intellect"（一般智力）的判断：**社会总体的知识能力，会越来越深地沉淀进固定资本、机器和技术里，于是单个劳动者的个人才能，不再是生产力的唯一载体。** 机器里装的是无数前人判断的总和，个人只需调用，不必重新发明。

Multi-Agent 把"一般智力"往前推了一格。过去，知识沉淀进机器，但"怎么判断当下这件事"仍要靠人临场调用；Multi-Agent 把"判断过程本身"也做成可编译的流水线，让沉淀不再停在资料和工具层面，而是进到"怎么下判断"这一层本身。一个人做的判断，经校验、经回流，最终变成一条谁都能执行的规则——这正是"一般智力"在脑力劳动上的兑现。

用得诚实：马克思关心的是资本与劳动的分配，不是我这套工程方法，我借的是他那半句话的骨架，"知识能力正在脱离个人而成为生产方式"。Multi-Agent 证明这件被预言的事，终于从被动的"能力存储"走到了主动的"判断生产"，而这也正是它像当年工厂改体力劳动一样改写脑力劳动的那个支点。

把"判断被写进系统"落到单笔，可以看见它到底拿走了一个人的什么、又留下了什么。过去一个老审在十分钟里完成一次判断，靠的是他脑子里几十年攒下的"这个东西我见过、大概会怎么走"，过程看不见，也搬不走；可编程化之后，同样的一次判断被拆成几步可追溯的动作：第一步把它切给一个 Agent，第二步让另一个 Agent 独立复核它的结论，第三步把这次的对错连同当时的上下文一起写进账本，第四步准确的规则回流成所有人都能执行的一条。一个人几十年的经验，不是被"复制"走了，而是被拆成几条谁都能复核的规则留了下来——这中间被拿走的只有"不可见"那一层，被留下的反而是比原来更可证明的判断能力。这一步才是"一般智力"从预言变成生产方式的那个瞬间。[内部项目实测]

## 三、对照生产史上的肌肉替代：这次换的是判断肌

回头看工业史，能看清这次替换的分量。蒸汽机替代的不是某一种肌肉，而是"动力"这个生产要素本身；电力替代的不是某一种工序，而是"能量传递"这把钥匙。Multi-Agent 替代的，也远超"某个脑力岗位"，是**"判断"这个脑力生产的基本要素**——它让判断不再附着于某个大脑，而是成为可以被调度、被治理、被复制的独立要素。

这引出一个不那么舒服的推论：脑力劳动内部的分工结构,会被重新画一遍。过去一个团队要十个人，是因为判断只能靠十双眼睛和十套直觉堆；当判断可编程化，团队的结构从"堆人"变成"分工明确的生产线"，个别岗位会被分解，个别角色会被升级成管规则、管治理、管回流的人。这正是《组织学的一课》那四根梁在行业尺度上的落地：分工重画、制衡重排、问责重指。

对比主流软件业又看到一层错位。今天的 Agent 框架把"让 Agent 接活"做得越来越顺，却很少追问"把一个判断迁移给系统之后，谁来证明它还和原判断师一样可信"。Multi-Agent 逼出的那个问题，恰恰是这场迁移里最容易被人省略、也最致命的那一步。

把"蒸汽机替代动力、电力替代传能、Multi-Agent 替代判断"这层比划开，三张替换并排看，能看清每一次迁移共同的海平面：

| 迁移 | 它替代的生产要素 | 替代走的是不可见性还是负责的人 | 迁移后那根更硬的线落在哪 |
| --- | --- | --- | --- |
| 蒸汽机 | 动力：让动力离开畜力 | 马可以少养，但"这批货要保证送到"的承运承诺还在 | 谁来为延误负责的契约线 |
| 电力 | 传能：让能量离开锅炉房 | 煤可以不用背，但"生产线不能停"的供给责任还在 | 谁维护电网稳定的调度线 |
| Multi-Agent | 判断：让判断离开某个大脑 | 专家可以调走，但"这个判断要保证对"的证明责任还在 | 谁给它复核、谁给它入账的问责线 |

这张表最有用的一句是中间栏：三次迁移都有人误读成"替代主体、责任可以散伙"，可真相是替代的从来只是"不可见的那个部分"，责任非但没走，反而因为不可见性这一层障眼法被抽掉，变得更硬、更可被点名。蒸汽机淘汰的是畜力，没淘汰"货要送到"的承诺；Multi-Agent 淘汰的是"判断要靠一个人的脑子"，没淘汰"判断要对"的证明。

## 四、对企业、行业、社会：生产力结构的重排

把落点放到最大，第十一篇要回答那个题目层面的问题——多 Agent 到底改了谁。答案不是"让公司出活更快"，而是三件结构上的事。

第一，对企业，判断从个体资历变成组织资产。过去专家的判断跟着人走，人走判断走；判断可审计、可回流之后，判断沉淀进账本和规则，组织第一次能"留住"自己长得最像人头衔的生产力。第二，对行业，判断的复制成本坍塌。手艺人式的判断没法规模化，可编程化的判断可以按需复制、跨团队复用，行业的产能上限从"存量高手数"变成"规则和账本的可扩展性"。第三，对社会，脑力劳动的分工被再分配。就像当年的工厂把体力活拆给机器和普通工人，Multi-Agent 会把一部分重复判断拆给系统，而把人更多推向"判断规则本身该长什么样"的治理层。

我料得到有人要泼冷水：这不就是又一轮让"聪明人能外包判断"的技术合唱。可 Multi-Agent 的要害恰好相反——它不鼓励把判断甩出责任区，它要求每笔判断都能被点名、被复核、被追责。迁移走的不是责任，是判断的不可见性；留下来的，是比以前更硬的那条问责线。

这句话不是姿态，我在内部项目里见过两种迁移的对照。[内部项目实测]一种叫"甩锅式迁移"：把判断塞给一个 Agent，人退出循环，错了也没台账，出了故障只能在事后互相指责"模型不行"。另一种叫"留痕式迁移"：判断仍在跑，但每一笔都带着校验者、规则版本、回流记录，出问题后能在三十分钟内回放整个决策链路、把断点指到具体的某根梁某行规则。两种系统跑同一类任务，我见到的是：前者第一次出错就进入"谁都不认账"的死循环，返工次数一路走高；后者出错后能当场定位、当场改规则，同类错误的复现率逐月下降。区别不在"有没有用 Agent"，在"迁移的时候把不可见性一起迁走了，还是把问责线一起留下了"。

飞升收进主线，第十一篇落成一句：

> **生产力的可编程化，是判断从天赋变成资源的迁移。** 判断一旦可分工、可校验、可审计，脑力劳动的生产方式就被结构性改写——对企业是能力资产化，对行业是复制成本坍塌，对社会是脑力分工的再分配。这条线的终点，就是第十二篇那本"熵的账本"。

这也给第十二篇《后记：熵的账本》递了棒。当判断本身变成可编程、可计量的资源，Multi-Agent 终于有了一本可以记的账——它记的不是钱，是每一次决策到底放进了多少结构、又留出了多少失控。

**谱系定位**：这一篇把前面各格的外拓收成一个总判断——研报自动化的"内容工业化"、SWE Agent 的"工程劳动力可编程化"、Agentic RPA 与 Copilot 的"操作层自动化"，本质是同一件事在不同脑力工序上的投影：判断从天赋变成可编程的资源。区别只在于迁移的深度与问责的完备度。我们不主张"每个应用都要变成 Multi-Agent"——很多单一、高频、少歧义的任务，用静态脚本或单 Agent 就够；Multi-Agent 只回答那些输出难自证、错了代价大的应用。外拓到这里，主线仍是一条，不是一张网。

## 第一天就能用的清单

- [ ] 把你团队里最依赖某位具体专家判断的那条链找出来，问一句：这个判断如果今天被调走，机构还能证明自己做得对吗？答不上来，就是它该先被可编程化的候选。
- [ ] 别把可编程化当成"把判断复读十遍"：每迁移一个判断，都要配上"独立校验 + 回流规则"两件套，否则只是把不可见从人脑挪进了黑箱。
- [ ] 画一张自家生产力草图：判断现在是"长在人身上"还是"沉淀在系统里"？两项占比，决定了你该先重画分工，还是先建问责。
