# 少数派也能对

> 多数一致不是真值的替身。很多 Agent 达成共识，只能说明它们错得相同；对抗决策要命的不是没人反对，而是反对被多数吞了，连账都没留下。

## 一、"全部都说对"，我反而不安

最让我心里发毛的，不是多 Agent 各执一词，而是它们异口同声。

有一回我把一个边界问题丢给五个模型，五个都给了同一个看起来头头是道的答案。按直觉这是最该放心的时刻——全体一致，还用复核吗？可我恰恰在那次栽了：那个"全体一致"的结论，是个顺着提问口气、又恰好彼此方向相同的漂亮错误。它们不是各自独立想对了，是共享了同一个偏见，然后互相壮了个胆。

我给第六篇立个靶子：**多数一致改不了判断的质地。** 面对一个不透明、不可证明的判断器，把它拆成十个 Agent 鼓掌通过，并不会让结论更可信——除非那十个判断之间，存在真正独立的证据，而不是互相复读机。

## 二、多数不是真值，是投票结果的代理

把决策交给多数，其实是把"谁对"换成了"会赢"。可会赢与会正确，是两回事。

孔多塞的陪审团定理论证过：假设每个投票者独立地、以超过一半的正确率做判断，那么人数越多，多数结果就越逼近正确；反过来，如果大家平均水平只有一半或者更低，人多不但没帮忙，反而会稳定地把错误放大到近乎必然。这给多 Agent 敲了一记最狠的警钟：**"多数聚合"不产生正确性，它只放大底层判断的偏置方向**。Agent 是同源模型、同批数据训出来的，它们之间根本不是孔多塞要求的"独立"——它们共享偏见的概率高得吓人。

所以多 Agent 的价值从来不是"问很多人，谁反正能答对"，而是：怎么逼出彼此独立的证据，怎么在多数成形时，不让那唯一清醒的一方被沉默。后者，正是 Multi-Agent 要补的缝。

## 三、孔多塞的三个前提，现实中逐个在塌

陪审团定理听起来理所当然，好用却在三个前提都必须同时成立的时候。我不能只引用定理当挡箭牌，得把它拆开看，每一条在真实的 Agent 环境里都在漏气。

第一条是**独立**。陪审团成员各自掌握的证据互不耦合，才会靠数量收敛到真相。Agent 恰恰在最要命的地方不独立——它们常常共享同一个底模、同一份 SFT 数据、同一套提示模板。我的经验里，五个同源模型对一个边界问题给出相同错误答案的概率，远比"各自独立猜中同一个错"高得多；这不是我拍脑袋，而是复读机效应的直接结果：同源意味着错法也同源，多数一致只是在把同一个偏置排版成"像是确认"。[内部项目实测]

第二条是**平均正确率过半**。定理假设每个人平均优于随机。可当任务超出模型的稳健区间——比如遇到嵌套、反事实、或措辞带陷阱的问题——这批模型平均可能就卡在五五开附近。此时人多不收敛到正确，而是收敛到那个已然过半的偏置。多数投票越热闹，越是在给一个均值偏置盖合格的章。

第三条是**无串谋**。定理假设不存在投机的合谋。但 Agent 共享上下文、彼此能看到对方的中间输出，这本身就是一种软串谋:最后一个 Agent 读到前面几位的结论后再作答，它的"独立意见"已经是前面的回声。三个前提塌了三分之二，多数还是那个多数，作为真值代理的资格却只剩形式。Multi-Agent 的应对，不是不再表决，而是给表决装上"这些人到底独不独立、均不均值过半、有没有串过谋"的前置质检。

这三条质检合起来，就是我把孔多塞定理从课本搬进代码时最先落地上的一条规则：**表决之前先验独立性，而不是表决之后拿结果当正确性。** 检验方式也很朴素——让每个 Agent 在看不到别人输出的隔离环境里先落一版判断，再进共享讨论；凡是讨论后才改口的票，单独标记为"受共识影响的意见"，不再和无影响票混在一起计。这一条改动很小，作用却很实：它让"多数"第一次能对得起"独立"两个字，而不是默认它们独立就完事。读书时觉得定理是锦上添花的数学，进工程后才知道它是 Multi-Agent 选型的硬约束。

## 四、Swarm 五相教会我的，是它没写的那条边

OpenAI Swarm 的五相是个很好的起点：例程 Agent 起手，handoff 移交证明其"权责可分"，上下文滚动累积，多数在流动中成形，最后产出。它的优雅恰恰暴露了它的缺口——**它把注意力全放在"任务该怎么流"，却几乎没写"分歧该往哪存"**。多数成形时，那个持不同意见的 Agent 只是移交链上不再被读到的一个节点，它的理由随上下文一起消散，事后无迹可寻。

我在 SmartQuant 里补的那条边，就是少数派异议通道：多数一旦成形到某程度，任何与被采纳观点相左的裁决必须强制留一行痕，写清它依据的证据与推翻前提。这条痕不参与表决，但它进复核——这正是第三篇三权分立里"验证人"要看的账。多数投完票就散场，是透支；分歧留过痕，才是资产。

什么叫"留一行痕"？我给的格式很死板，恰恰是死板才好复核。每一行必须落四个字段：谁出的异议、依据的证据、要推翻的前提、以及验证人对这条痕的处理结论。缺一个字段就判这条痕无效，退回补。这一步把"尊重异议"从态度翻译成了可被校验的数据结构——没有这个 schema，所谓"给少数派留通道"就只是一句漂亮话，验证人依然无账可翻。[内部项目实测]

## 五、对照 AutoGen / 表决框架：共识机制不等于事实机制

主流框架里，"多数表决"被当成事实机制在用。AutoGen 这类编排里常见到：让多个 Agent 各自作答，取票数高者当结论。这干的是把"一致性"当作"正确性"来消费。

我必须推翻它。表决只能回答"此刻谁更可能被认同"，回答不了"这个答案符不符合事实"。一个 Multi-Agent 对二者必须分开记账：表决结果进"社会账"（谁被认可），复核证据进"事实账"（对不对得上证据）。若把社会账当事实账用，等于默认"多数必然更接近真相"——而孔多塞的整个定理都在提醒我们，这只在两个前提下成立：成员彼此独立、且各自正确率过半。**同源多 Agent 基本满足不了第一条。** 故而共识该是线索，不该是结论。

现实里最常踩的坑，是"全体一致终态"。我见过一种假性收敛：五个 Agent 讨论到最后都改口同意，是因为它们被同一个强表述说服，而不是被同一个事实说服。表决结束了，账却从来没记过"它们当时各自信的是什么"。Multi-Agent 要记得是分歧的轨迹，不是掌声的高潮——这也顺带解释了为什么六篇下来，我一直把"异议留痕"看得和"多数聚合"一样重。

AutoGen 的表决机制值得再往下拆一层，因为它把"分歧"处理成了纯收尾动作。拿它的群聊编排（GroupChat）来说：多个 Agent 在一个共享会话里轮番发言，代码会执行、结果会贴回，最后通常由一个"汇总者"把对话改写成结论。问题不在"有主有从"，而在它把分歧消化在对话里，而不是沉淀进账本。那几个 Agent 为了任务进展，倾向于收敛到最近的共识，唱反调的那位被"说服"了，它原来的判断没有单独立项。Multi-Agent 把这称作"共识池泡没了异议"：不是它们没吵过，而是吵的痕迹随对话一起丢掉了，事后没人能回答"这结论当初是被哪些证据压过来的"。表决机器擅长制造结论，Multi-Agent 擅长保留推导——第六篇站的就是后者这一侧。

再补一个我确实栽过的反例，作为本节的反面教材。有一次我们让五个 Agent 评估一个策略是否该上马，四票赞成、一票否决，我们按多数放行了。事后复盘才发现，那唯一的否决票引用的是一条历史回撤数据，四张赞成票给的是同一个乐观分板。放行当天策略就脱了轨。错不在多数，错在我们把"四票"当成了"四个独立证据"——它们同源、同数据、还被同一个乐观 prompt 带偏过。修正也很直接：凡是出现"独票反对且引用数据"，default 先别急着多数通过，把那条数据拉进复核流程再决定。这句话后来被写进了我们的门禁清单，成了"一票带数据的异见优先复核"那条的由来。[内部项目实测]

## 六、原理飞升：可复核的共识 = 独立证据 × 少数异议留痕 × 事实账独立记账

收进主线，第六篇在 Multi-Agent 里的位置是这样一句话：

> **可复核的共识 = 独立证据 × 少数异议留痕 × 事实账独立记账。** Multi-Agent 不追求"大家意见一致"，它追求"一致恰好等于正确"——而达成后者，靠的不是让多数闭嘴，是把少数的话留下来、交给独立的账去审。

诚实地讲，反共识做起来更亏眼前：多数已成形，你还偏要去听那个唱反调的，费力又添乱。可这正是尊严所在。小系统可以"全票通过收工"，链一旦要可证明，那些被多数压下的另类判断，才是防止集体走偏的要害。对抗决策的真正负责人，是那个愿意把异议写下来、而不是让它消失的机制。

这也给第七篇递了棒。《宣称对齐事实》要处理比"谁对"更根本的问题：就算你捞回了少数派观点，怎么证明一个"宣称"真的对齐了事实——怎么给判断厂装一把能对着证据反复核对的标尺。多 Agent 从"判得准"，再往前走一步到"证得死"。

**谱系定位**：这一篇正面对话"多 Agent 辩论·对抗"这一格——无论是 OpenAI Swarm 的对抗、还是各种 debate / debate-chamber 框架，都在问"多角色怎么碰出正确答案"。我们的立场是：对抗的价值不在让多数好听，而在把少数异议留痕、交独立的账去审。相比"RAG / 研报自动化"那种"检索到一致结论就收工"的朴素多数，Multi-Agent 拒绝让票数冒充证据；相比"Agentic RPA / 企业 Copilot"那种"让流程跑通就算对"，它坚持每一个结论都要回答"凭什么不是那个唱反调的人对"。对话式多 Agent 不一定需要这一格，Multi-Agent 非它不可。
