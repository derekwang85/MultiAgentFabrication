# 宣称对齐事实

> 一句话占的情报位置有高有低：真正能打分的，是那种把"什么会推翻我"也一并交出来的宣称。Multi-Agent 要的不是"听起来对"，是"说得出在什么证据下会翻车"。

## 一、一句漂亮话，怎么就成了不敢较真的分

我见过一种系统病：Agent 给出来的结论句句笃定，评分表上也好看，可一旦追问"哪种情况会让你改口"，它答不上来。

问题不出在模型错，出在宣称本身没被加工。上一篇拿回了少数派异议，可就算一个观点写了下来、存进了账，它顶多是"有记录"。能不能被当成可信判断，还差一道工序：这个宣称，到底对什么证据负责？Multi-Agent 里，"言之凿凿"和"可被证伪"是两种完全不同等级的资产。

我给第七篇立个靶子：**一个不能说出"什么会推翻自己"的宣称，不配被打分。** 打上去的分，不是它的实力，是它模糊换取的空头。

## 二、可证伪性，是宣称对齐事实的入场券

卡尔·波普尔用一个很狠的标准拆开了科学与非科学：一个断言要算数，必须先说清"什么样的可观测结果，会让它被证伪"。占星术永不失手，是因为它怎么说都对，从不给自己留翻车的口子——恰恰是这种"永不输"，让它退出了可检验的领域。

这套逻辑搬到多 Agent 身上就是回旋镖：谁的宣称越模糊、越会自圆其说，谁就越没有对齐过事实。越是不肯给反例留门的话，越是没法被任何证据校正。Multi-Agent 的核心不是"让模型更会讲话"，是把它讲的话，一步步加工到"能对着证据读数"为止。

所以可证伪不是学术洁癖，是入口把关。进场打分的每一条宣称，都要先答：哪条证据、什么读数，能让它脸红？答不出，就不让它上桌。

## 三、基准对照 Gauge：给宣称装一把能读数的标尺

光说"可证伪"还空，得做成能落地的结构。我给 Multi-Agent 加了个东西，叫基准对照，英文还叫 Gauge——一条拿着参考值、对着证据读数判定的标尺。

加工路径如图 7：模型吐出一条宣称，第一步不是打分，是把它揭成"可推翻的断言"，逼出"什么证据能让我翻车"；第二步为这条断言定一把基准标尺，写清参考值 + 触发线；第三步才是拿读数对证据，得出对齐或不对齐的判定。分不在开头给，在标尺读数出来后才给。

第一步那个"揭"字最容易被跳过，也最该较真。揭得好不好，能一眼分出等级：真宣称给出的翻车条件可以查、会带着一个具体的读数阈值（"回撤到 3.2% 就翻车"）；假宣称给的翻车条件只有比喻、没有数字（"表现变差就翻车"）。前者能对证据读数，后者对着什么都能点头——它不是在诚实交代死穴，是在用一句漂亮话把死穴藏得更深。所以第一步的验收标准就一条：翻车条件必须落到一个"能填进读数表"的字段，填不进去，就当这句宣称还没揭干净，退回重揭。

我把对立面也画进去了，叫假分陷阱：没有标尺就打分，宣称越模糊，分越虚，等于拿模型的自信千金买了个空镜。主链是三步审，支链是无标尺的假账——Gauge 要拦的，正是那条假账的岔路。

## 四、一张加工表，把宣称钉在标尺上

抽象地说"装标尺"谁都会，落到表格才有用。我给 Gauge 的每一步都定了可抄走的字段，拿 Multi-Agent 里真实发生过的一桩事喂进去。

那件事是关于要不要放量：「给某策略上自动化回测」。模型吐出一句宣称：`回测通过率 87%，可以放量。` 放到 Gauge 的第一步，先把它揭成可推翻的断言，逼出翻车条件——`若取样窗口不足 13 个交易日，或止损线内回撤实测超 3.2%，则此宣称不成立。` 第二步定基准标尺，写清参考值（`最近一个季度逐日撮合成交记录，共 57 个交易日`）+ 触发线（`有效样本下限 40 个交易日；回撤阈值 3.2%`）。第三步才是拿读数对证据（`[内部项目实测]`）：实际只取到 21 个有效样本、回撤峰值 4.1%，双双落在触发线内侧，判定直接翻转为 `不对齐，禁止放量`。

这张表厉害在第三行：判定不是人拍脑袋，是**自动判定**。参考值、触发线都是提前写死的字段，模型只负责把读数填进去，一跨线，标尺自己翻。分不是开头的自信，是这一步读完读数后才发的红利。值得抄的就三栏：`宣称 / 参考值来源 / 触发线`，缺哪栏，宣称就回炉，别上桌。

触发线定下来，还有个隐蔽的坑要认：标尺放得太松，等于把"读数"变成了走过场。一次我们给通过率设了 `≥40% 即放行`，那是照历史均值的下沿拍的——结果一批明显没到火候的实验全被判定成了"对齐"，读数倒是对的，只是尺子压根没量到要害。触发线不该拿历史均值当默认值，它得对准你要避免的那个具体后果（回撤爆仓、准确率跌破可用线），否则自动判定越利落，假放行越多。尺子放得太松的打分，和无标尺打分，是同一件事的两种说法。

## 五、无标尺打分的翻车现场

光讲结构还不够，得让代价长出血肉。Multi-Agent 早期走过一段弯路，就是红线第四条「无标尺就打分」的反例 `[内部项目实测]`：一个 Agent 拿 `字面一致性 92%` 的成绩单上了线，评分表里齐刷刷的高分，可它实际上是在对一份**过期的配置快照**做判定，参考值早已作废 11 天。字面答案它对得极准，因为你拿什么旧文档喂它就回什么旧答案——流畅、笃定、全部命中，唯独没碰一次真证据。

那 11 天里它产出的判定全部作废，团队是在一次下游报错里顺藤摸到的。教训不是"模型越狱了"，是**没有标尺的分，把"回得平"当成了"证得死"**。promptfoo 这类工具测的是前者，测得出 92% 的字面命中，测不出"参考值过期"——因为参考值是否有效，根本不在它的字段里。要在 Multi-Agent 里活下来，字面一致性归测试工具管、宣称与事实的对齐归基准对照管，这两本账一混，就等于默认"说得通即是对的"。多数一致和证据成立差着一个孔多塞的距离，这里还要再补一句：字面顺口和证据成立，差着一条被证实的参考值来源。

事后复盘，我们把这次踩坑压成了一条可执行的检查，专门用来拦住"报得出分数、报不出证据出处"的宣称，叫**证据出处三问**：这条参考值是哪份记录采的？采于什么时刻？采完之后有没有人改过？三问里任一答不上来，宣称就不进打分，直接标"证据出处缺失、退回补证"。补证不是逼模型重说一遍，是去戳它背后的数据管道：那条过期配置是谁同步的、触发器为什么没响。答案要是又落到"靠人记得"，就说明这条宣称还没资格被读数——它先得把自己的可信度，交还给一条能被追踪来路的证据链。

这套三问也在教你分辨哪条宣称值得花力气：真宣称会带着可指认的来路（哪份快照、哪个时点、谁经手），假宣称只肯给一个流畅的结论。差别不在语气，在有没有一条你能顺藤摸瓜的证据根。Gauge 的第三步读读数之前，先过这一步——读数读得再准，读的得是活数据，不是 11 天前的尸体。

## 六、给标尺也上一把标尺

翻车现场追到底，罪魁不是"没打分工具"，是**标尺本身就是过期的**——参考值作废 11 天，可 Gauge 里没有一栏显示"这个参考值什么时候失效"。

那就得承认一个更难看的递归：宣称要对证据负责，可证据也得对更上游的东西负责。参考值是谁给的、什么时点采的、还活着吗，这三问不答，标尺就是一根画在沙地上的尺。Multi-Agent 管这个叫给标尺上标尺，做法很便宜但极硬：每把 Gauge 加第三栏 `参考值来源 + 失效线`，失效线一到，标尺自动作废、宣称回到待审，不许静默续命。这样"过期配置"那种事故就变成了纸面规则，不用等人抓到再补。

诚实地说，这条也会顶到天花板：写死的参考值来源本身也可能写错，谁能给它上标尺？我给的裁决不是无限递归，是**在失控点让位给人**。参考值来源的有效性判不了自动，就列为人工复核的固定时点，写进规格里、由第 8 篇的治理规矩来兜底。Gauge 负责把能读数的话拦住，拦不住的、需要人拍板的，明确标记"此栏需人工复核"——它不假装自己无所不能，这正是它比聊天助手诚实的地方。

## 七、原理飞升：宣称对齐事实 = 可证伪 × 基准读线 × 无标尺禁打分

收进主线，第七篇给 Multi-Agent 补的是这么一处：

> **宣称对齐事实 = 可证伪 × 基准读线 × 无标尺禁打分。** Multi-Agent 不发"听起来对"的奖，只发"说得出在什么证据下翻车、且读数真对上了证据"的奖。分是标尺读出来的红利，不是自信换来的空镜。

诚实地讲，给每条宣称立标尺，短期又是亏的：多问一句"什么能推翻你"，拖慢节奏还显得刻薄。可这正是 Multi-Agent 和聊天助手的生死线。聊天助手可以靠话术取悦，Multi-Agent 一旦喂养"模糊即高分"，账就烂在源头——后面所有三权复核，都是在给一个假分洗地。可证伪，是让 Multi-Agent 对证据负责的第一道闸。

这也给第八篇递了棒。《治理优先于调度》要回答：当多 Agent 的链条真的长起来、判定真的多起来，靠什么让整条链不敢造假、不敢空转——规矩怎么前置，比任务怎么派更重要。

**谱系定位**：这一篇横跨"SWE Agent / 编排框架"与"RAG / 研报自动化"两格——凡是输出会被当真的系统，无论是代码变更、研报结论、还是 Copilot 建议，都需要"宣称对齐事实"这条底线。我们刻意没有把这一节扩到"Agentic RPA"那一格：RPA 的流程正确性靠脚本与断言就能钉死，而 Multi-Agent 面对的宣称，往往是"这句漂亮话在什么数据下翻车"这种没法靠排程验证的东西。给宣称装标尺，是 Multi-Agent 拿来跟所有"看起来对"的应用划清界限的那把尺。
