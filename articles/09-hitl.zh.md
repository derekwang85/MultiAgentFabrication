# 人不进圈才是浪费

> 我把人从"兜底"的位置挪到了"闭环"的位置，Multi-Agent 才第一次把自己接成整圈。凡把人留在圈外当观众的系统，不是更自动，是更聋。

## 一、最贵的浪费，是人被请来但没接上

我见过一套标榜 HITL 的系统：流程图上画着一个人形节点，写着"人工确认"，可你顺着数据流看进去，那个人形节点从没真正拦住过任何东西——Agent 出的结论直接放行，人只在事后收到一封没人读的归档邮件。

这不是节外生枝的疏漏，是设计上就把人当成了摆设。做系统的人把 HITL 当成"进个按钮、加个审批、显得更负责"的装饰，而没理解：**人在 Multi-Agent 里的位置，不是一个可以鼓掌的看客，是一条让判断能闭合成圈的回流线。** 人一旦不在圈上，整个系统不是更高效，而是更聋——错误照发，教训不回，判断永远学不会。

我给第九篇立的靶子：**人不进圈才是浪费。** Multi-Agent 要的可证明性，不是靠 Agent 的自证，是靠人这只真手在关键处把闸、并把教训编译回规矩，才第一次真正闭环——这一步，没有哪台自动机替得了。

## 二、HITL 是闭环，不是妥协

把 HITL 当成"自动化的退让"是普遍的误读。仿佛系统做得越好，人就该退得越远，直到彻底下岗。可 Multi-Agent 的物理约束摆在那里：Agent 的自信值和它的正确率不是一回事，自动化越顺，某些高杠杆决策点的单点失效越被漂亮的流转掩盖。

所以我把 HITL 放进一次循环：Agent 主流程先跑，跑到设好的决策点，交人确认；人的一次纠正，不是只改了这一单，而是被编译成确定性不变量，回流入账；下一条规矩从此自动拦住同类错误。人的价值不在"看有没有错"，在"看错在哪一层、把它做成规矩"——这才是人能贡献、Agent 独自学不会的那一环。

这条"回流动作"得有形状，不然又会沦为口号。我在内部项目里把它落成一行可核对的留痕记录，[内部项目实测] 每一位数都是机器能复核的字段：

```text
case=Q-1042  layer=routing  ruling=block(quant-s, cost)  invariant=if cost>0.4 then not quant-s  author=human  ts=2025-06-11 14:32
```

它写的是：第 Q-1042 单，错在路由层，人类把"成本超 0.4 就别用量化模型"这句教训编译成了一行确定性不变量，写进了账。此后只要调度层再撞上成本超阈的任务，这条规矩就自动拦下，不再等人复述同一条教训。人做的不是"批准这一单"，是"从这一单里抽出一条以后都不用再改的判断"——回流有没有真的发生，看的是账里有没有长出这类行，不是界面上有没有人点过"批准"。

Multi-Agent 的核心主张 A6 在这里收束成一句：**人不进圈才是浪费 = 关键点进圈 × 纠正编译成规矩 × 教训回流闭环。** 自动化负责把流程跑顺，人负责把判断做对，缺了后一半，前半段跑得越快越危险。

## 三、控制论：反馈才是让系统活下去的东西

我往这个认识上靠一个源头，借的是维纳。诺伯特·维纳在其《人有人的用处》里反复讲一句话：**有效生活，就是要靠足够好的信息去生活**（"To live effectively is to live with adequate information"）。控制论的起点就在这里：系统不是靠"输出够漂亮"证明自己活着，是靠**反馈**不断校正自己，才朝目标收敛。

把这句话翻到 Multi-Agent 里，就是别把 HITL 当成一次性的门禁，而要当成一圈一圈转的回流。Agent 下单、人纠偏、规矩更新、再下单，这一圈每转一次，判断的可证明性就长一寸。凡是没有这一圈的，哪怕单个结果再准，也只是在赌运气——因为没有反馈，错误不改结构，重演的只是更密。

用得诚实一点：维纳那个时代还没有 Agent，我借的是他那套"反馈定生死"的骨架，不是预言。多 Agent 为什么特别需要 HITL？正因为 Agent 之间天然没有"自知之明"，必须靠一只圈外清醒的手，把一次试错变成下一次的免疫。

这圈反馈拧多紧才算数，我给一条可测的判断：每转一圈，账里必须长出一行以前没有的不变量。假设第一圈，人因为"某类催收任务不该自动外呼"截下了一单，账里多了条规则拦它；第二圈，同样的判断已经由机器自动做了，人只是看到它在"已经拦下"的状态——这一刻 HITL 才算真正闭环，因为人的教训已经长进了结构，不再需要人每次都重复。反过来说，如果同一个改判在一个月里重复出现三次以上，而账里一条新规则都没长出来，那说明这个"人进圈"是摆设：圈在转，但什么也没学会。用这条尺子去量，HITL 是闭环还是符号，一眼就分得清。

## 四、对照 AutoGen / 常用编排：你的 HITL 是闸门还是符号

主流框架怎么处理人工？以 AutoGen 为代表的编排框架，把人工入口做成"某些节点可以暂停、等人回话"的能力——这解决了"人能否介入"的工程问题。可各框架默认几乎都不扛"介入之后做什么"：人给了个改判，改判的教训存进哪条规则？下次同类场景会不会自动拦住？多半没有。

这就是我要区分的东西：**用当闭环的 HITL，和挂当符号的 HITL。** 前者以"人的纠正是否回流成可复用规则"为验收标准；后者只看"流程图上有无人工节点"。Multi-Agent 只认可前者——一个从来不改结构的人工节点，只是让这张图看起来更负责，实际是在为不可证明的链盖负责人章。

一旦把 HITL 当符号，就会出现最典型的事故：人确认了一单，也确认了下一单，可他确认时看到的信息和上次一模一样，系统根本没把他纠正过的认知带进来。Multi-Agent 要的，是让每一次人工介入都沉淀成下一条不变量，而不是在界面里再点一次"批准"。

AutoGen 把"介入之后"这一棒交给谁，恰恰是框架默认里最空的那一格。它给了暂停节点、给了等人回话的握手，可回话落下后，这条教训归到哪条规则、由谁编译、写不写账，多半交给你去焊。焊得勤的人，把它接回一条不变量并进账；焊得松的人，那个"人工节点"就成了字面意义上的摆设——图上有个人，判里没人。框架替你解决的是"能不能停下问人"，Multi-Agent 要的是"问完之后这一问有没有长出规矩"，后者只能靠你自己接。[内部项目实测]

把 HITL 放到第十三篇的四层记忆总线里，人的位置就有了一个更精确的名字：**人，恰恰站在 k4 那根跨层回流管道的裁决位置上。** 上一节说"人的纠正要编译成规矩"，可这条规矩从"产品层的现场经验"升格成"元层下次造东西要用的规则"，中间隔着的那道闸，就是人。机器可以自动把经验提纯成候选、把证据摆上桌，但"这一条到底值不值得改规矩、改了会不会伤到别的零件"的终裁权，我只交给圈外的人工——这正是 k4 设计的"单向、带 ADR、有人终裁"那三根梁里的最后一根。于是第九篇和第十三篇在这里接上了：为什么人不能是符号？因为符号不是裁决者，它不担"要不要把一次试错升格成一条所有人今后都得遵守的规矩"这个责；为什么人不能是代打？因为代打不裁决，它只是被流水线冲过的手套，只会点"批准"，不会从一次个案里抽出那条该进账的规则。HITL 的每一次真正的介入，本质都是 k4 回流管道上的一次带审计、有方向、经人落签的规则升级——这一步做不做得到，决定了 Multi-Agent 的记忆是只会越积越聋，还是会真的长成能自我收紧的规则系统。[内部项目实测]

## 五、失效模式：决策点认得太勤，人就成了代打

HITL 还有一个常见的失效方向：不是人没进圈，而是圈里塞满了人。为了让系统显得更"受控"，有人把高杠杆决策点、低杠杆决策点一股脑都挂上人工确认；结果人是进了圈，可进得太频、太密，来不及看，于是退化成"快手批准机"——只点不判，看见就差一格的红色就放行。这也就是那句老话的翻版：闸门设得越多，每道闸门就越没人真看，因为人的注意力被流水线摊薄到每道闸上只剩零点几秒。

这跟"人当符号"是同一个病根的两张脸。当符号是挂着给人看；当代打是放着当作坊手套。两者都丢了 HITL 的本意：**人在关键点并不是做"我确认了"这个动作，而是做"这个改判值得编译成规矩"这个判断。** 决策点挂得越多，单点判断越被流水线冲淡，人越没有余力去抽样、去复盘、去把一次纠偏沉淀成不变量——链不仅没更可证明，反而因为它"看起来更受控"而更危险。

所以 Multi-Agent 在设决策点时要反着来：宁可少挂，但要挂得准。每个套着人工的节点，都要能回答"这个点为什么要人来，人来之后动的是哪条规则"；答不上来的决策点，要么撤掉，要么留给机制去判断，而不是无差别地把人都拴在流水线上数数。人不进圈是浪费，人进错了圈、进太密，一样是浪费——进的姿势不对，跟没进一样不划算。

## 六、原理飞升：人是 Multi-Agent 的最后一圈

收进主线，第九篇在 Multi-Agent 里的位置是这样一句话：

> **人不进圈才是浪费。** 自动化负责把流程跑顺，人负责在关键点把判断做对；Multi-Agent 敢不敢自称学到了东西，取决于它有没有把那句纠偏编译回规矩、并让它挡住下一次同类错误——闭环不接上，进步就是一个漂亮的词。

诚实地讲，把人工接进循环有一点别扭：自动化图上多了"等人"这个等待点，看着像在拖后腿；可这正是 Multi-Agent 和"自动玩具"的分界。玩具追求无人值守的顺，Multi-Agent 追求越转越稳的闭环。人这个环节放进来的不是速度，是把错误变成免疫、把单点变成结构的那只手——这也正是第四幕要飞升的地方。

这层别扭会让人产生一个真实的诱惑：把"等人"的节点做成可跳过，平时全是自动放行，只有出大事才"捞一次人出来盖章"。可这恰恰把 HITL 又踢回了符号——没人抽查，就等于没人在圈；判断的可证明性指望不上一个平时不睁眼的闸口。真把人不当浪费的做法，是宁可让关键判断慢那几秒，也要让那只真手长期在线：它不误在速度上，而是误在"看得准、改得对、沉得下"——这三点没有一样能被 Agent 自己的自信值替代。

这也给第十篇递了棒。《组织学的一课》要把前三幕的调度、治理、HITL，当成一个微观组织来读——Multi-Agent 三权分立、问责分明、控熵闭环的样子，正是组织物种反复演化出的那张脸。

**谱系定位**：这一篇划清了本系列和"Agentic RPA / 企业 Copilot"那一格的关键分歧——许多 Copilot 把人放在"兜底看一眼"的位置，平时全自动、出事才捞人，本质是把 HITL 当成了符号。Multi-Agent 反着来：人必须在关键决策点长期在线、且手柄一拉就要改变系统下一跳行为，否则就不算在圈里。相比"SWE Agent / 编排框架"里那种"人工审核代码变更合并"的环节,我们要的是人参与判断本身、而不只是放行产物。无人值守的 RPA 可以没有人，Multi-Agent 恰恰是那类"宁可慢几秒、也要人接住"的系统。

## 第一天就能用的清单

- [ ] 找出一条你天天跑的高杠杆链，在它的关键决策点把人真接进去：一次确认要能改变这条链的下一次行为，而不只是放行。
- [ ] 给每次人工介入配一个"回流动作"：人的改判必须被编译成一条可以由机器复核的规则，进账留痕。
- [ ] 用一张清单自检你有几个"人工节点"：凡改判后系统行为不变的那个，要么补上回流，要么删掉，别留着当符号。
