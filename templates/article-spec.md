# 文章 Spec 模板

> 每篇文章动笔前，必须先写 spec。spec 是文章的"设计图"，写清楚了再动笔，边写边想 = 边砌边设计 = 灾难。
> 对应 derekcoding-framework 方法论 02 Spec-Driven Development。

---

## 基本信息

| 项 | 内容 |
|----|------|
| 篇号 | 第 X 篇 |
| 标题 | （主标题：副标题） |
| 核心主张 | （一句话说清楚这篇要讲什么） |
| 目标读者 | （技术负责人 / 架构师 / 资深工程师 / 其他） |
| 预计字数 | 3000-5000 字 |
| 所属层次 | 战略层 / 架构层 / 契约层 / 门禁层 / 实现层 / 横向能力 / 收尾 |

## 验收标准

这篇文章写完了，怎么算成功？

- [ ] 核心主张在第一段和最后一段都有呼应
- [ ] 每个要点都有对应的项目实证
- [ ] 清单里的每一条，读者看完就知道怎么做
- [ ] 没有超出 2.2 列出的"不讲什么"的范围
- [ ] 通过 G1-G6 全套门禁
