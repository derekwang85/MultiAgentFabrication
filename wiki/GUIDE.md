# llm-wiki 使用指南 · GUIDE.md

> 这份指南教你用 `wiki/`：一份同时服务**人**与 **Agent** 的可查询概念索引。
> 它和另外两份文件分工不同——`index.md` 是检索入口，`AGENTS.md` 是建设规约（新增条目才读），本文件是使用手册（先读它决定接下来该怎么办）。
> 若你此前没接触过这份 wiki，先花两分钟读这一页，其余问题再顺着它的指引走。

---

## 一、它是什么：一份可查询的概念索引

`wiki/` 不是项目的正文，也不是阅读型方法论文档，而是一层"概念提取层"。它把两样东西蒸馏成短条目：

- 本项目**自身方法论**（`constitution/`、`docs/WRITING-FRAMEWORK.md`）出的核心概念；
- 本项目**所依赖的写作 skill**（derekwritting-evolution 等）里与该系列意志一致性高、值得留存的结论。

每个概念页只回答五件事：一句话定义、来源、落在框架哪一层、和谁互链、内化强度。因此它是给人快速定位、给 Agent 快速取证的公共层。

| 文件 / 目录 | 作用 |
|---|---|
| `GUIDE.md`（本文件） | 使用手册：怎么查、怎么溯源、什么时候该加条目 |
| `index.md` | 唯一入口：检索协议 + 概念地图 + 源索引 |
| `AGENTS.md` | 元规约：wikilink 语法 + W1-W4 建设门禁 |
| `concepts/` | 概念页（按五层分类）＋ `taxonomy.md` 分类法 |
| `sources/` | 一手源索引页（追溯本项目资产 + 依赖 skill） |
| `log.md` | 每次新增 / 修订的变更记录 |

## 二、给人类的阅读路径

你带着一个写作或方法论问题进来。通常不超过三步能到答案。

### 2.1 查一个概念

从 `index.md` 的概念地图往下找，它按五层排好（战略 / 架构 / 契约 / 门禁 / 实现）。

举三个实际查询的例子：

- 你在纠结"这篇要不要让 AI 自己给自己打分" → 查 `reviewer-writer-separation`，它会告诉你`分离是手段，评审者必须与写作者不同角色`。
- 你在想"下篇目标分定多少" → 查 `evaluation-driven-progression`，它给的是`严格大于前序均值、留 0.2 余量`的规则。
- 你在纠结"能不能用某个外国名人名言" → 查 `allusion-isolation`，它给的是 R1-R4 判定。

### 2.2 读一张概念页

每页固定四段，顺序别乱：

1. 头部三行（一句话定义 / 来源 / 相关 / 实证）——30 秒内判断这条是不是你要的；
2. `定义`——展开；
3. `证据出处`——指向源页或项目原文；
4. `内化级别`——**A 强内化**（项目默认，跟指定达成硬约束）还是 **B 弱内化**（软约束，凭语境判断）。

### 2.3 溯源一个一手来源

概念页来源链接到 `sources/` 的源页，源页再跳回一手材料（`constitution/`、`docs/`、`writing-harness/`、skill 文件路径）。判断一条经验的可信度，就看它能不能从这里走回一手出处——走不通，就标记为待核验。

### 2.4 什么时候该加一条概念

如果出现以下情况，才值得新增概念页；否则忍住：

1. 你已有一个**跨多个源收敛**的结论，且反复要用；
2. 一句话定义能在 30 秒内讲清它约束的是哪个写作或工程决策；
3. 有明确的一手来源或项目原文可指认。

只在单次写作里用到的一次性经验，不进概念页，就地记在写作留痕里即可。

## 三、给 Agent 的检索协议

被要求用这份 wiki 回答问题时，按下面的顺序走，用最少的读取找到可回验的答案，不空读、不跳读。

- **该不该查**：问的是本项目方法论 / 概念 / 决策依据 → 该查；纯技术实现或平台操作 → 不查，去查对应手册。
- **四步检索**：读 `index.md` 缩小范围 → 打开候选概念页用一句话定义验证 → 需要证据时沿 `来源/实证` 跳 `sources/` 取一手出处 → 需落到纪律时回链到 `../constitution/`、`../docs/WRITING-FRAMEWORK.md`、`../writing-harness/`。
- **收束**：命中 → 只引一句话定义 + 来源（不回抄定义段）；未命中 → 若疑似概念盲区则返回"答不上"并标记待补，否则给最近相邻条目。

写入 / 修改本目录前，必须先读完 `AGENTS.md` 与 `index.md`，否则不许落笔。

## 四、给 Agent 的落笔协议（新增 / 修订）

新增或修订条目必须满足 `AGENTS.md` 的 W1-W4 门禁：

- **W1 溯源**：每个概念必须有来源；无出处即不合格，实证必须可指认。
- **W2 结构**：四段齐全；定义一句话；不复制 source 或方法论文本原文。
- **W3 语言**：信号词密度 < 6/千字；不用"毫无疑问"类断言词。
- **W4 链接**：wikilink 有效、双向可达；链接目标必须存在于本 wiki，或回指项目原文路径。

两条纪律和内容质量同样重要：

- **失败安全**：AI 可先产出 `.draft.md` 草稿，但**定稿写入 `concepts/` 或 `sources/` 必须经人工确认**。没确认，草稿只留在 `concepts/drafts/`，不进入导航、不参与校验。
- **变更留痕**：每次新增 / 修订在 `log.md` 记一行：改了什么 / 为何 / 来源。删除或降级条目要写理由，不允许默默移除。

## 五、执行入口与校验命令

在项目根目录运行门禁脚本，可对单文件或整个子目录执行：

```bash
# 五道通用门禁（对人/Agent 成稿都用它），中文稿用 writing-gates.py，英文稿用 writing-gates-en.py
python writing-harness/writing-gates.py wiki                 # 仅 wiki 根级文件（不递归）
python writing-harness/writing-gates.py wiki\concepts        # 概念页
python writing-harness/writing-gates.py wiki\sources         # 源页

# 退出码：0 = 通过，1 = 未过，2 = 用法错误
```

两点提醒：

- 门禁脚本对目录**不递归**，`concepts/` 与 `sources/` 要分别跑。
- wiki 元规约（`AGENTS.md`、`log.md`）是协议文件，不适用 G5 内容评审，其质量留痕在 `../docs/WRITING-FRAMEWORK.md` 评审记录；内容页评审记录统一指回那里，不逐页另写分数。

|---|---|
| 快速找概念 / 源 | `index.md` 概念地图 + 源索引 |
| 用规范四段新增概念页 | `AGENTS.md` 第四节（模板） |

| 判断"该不该新加概念" | 本文件 §2.4 |
| 给 Agent 下"查一下"的指令 | 本文件 §3 检索协议 |
| 更新后校验、留痕 | §5 校验命令 + `log.md` |
